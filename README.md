## 第一部分 项目概述与边界

### 1. 项目定义

Coin Circle 是一个基于主体建模（Agent-Based Modeling, ABM）的封闭社会经济模拟与实验平台。系统由若干具有不同身份、经济状态、行为倾向和社会关系的 Agent 构成。Agent 在统一模拟时间下进行工作、消费、储蓄、交易、借贷和信息交流；个体行为通过经济事件与社会交互相互影响，形成可观察、可记录、可回放的群体过程。

| 项目理念｜Where money moves, people change. / Money moves. Agents react. Society emerges. |
| ------------------------------------------------------------------------------------ |

| 核心原则｜Simulation determines what happens. AI determines how it feels like being there. 模拟规则负责经济事实和状态变更；LLM 负责受约束的信息处理与自然语言表达，不拥有直接修改世界状态的权限。 |
| ------------------------------------------------------------------------------------------------------------------------------------------- |

### 2. 双重目标与成功标准

| **目标** | **目标陈述**                                               | **最低成功证据**                           |
| ------ | ------------------------------------------------------ | ------------------------------------ |
| 研究     | 研究 LLM 作为 Agent 间社会信息转述接口时，是否重构原始信息，以及重构是否传导为群体经济行为变化。 | 可重复转述机制实验、明确输入基准、至少一组可计算指标。          |
| 工程     | 构建不依赖玩家持续干预即可运行的多 Agent 经济模拟核心。                        | 模拟时间独立推进；Agent 自主行动；状态变更受规则验证；事件可追踪。 |
| 展示     | 让观察者理解 Agent 活动、经济变化、信息传播和实验结果。                        | 垂直切片、回放数据、图表或数据面板。                   |
| 能力证明   | 形成可审查的代码、实验、文档和展示成果。                                   | 可运行仓库、README、测试、实验配置、数据样例和 Demo。     |

### 3. 项目范围与非目标

| **级别**     | **范围**                                           | **说明**                |
| ---------- | ------------------------------------------------ | --------------------- |
| 【确定】核心     | 模拟时间、Agent 状态、基础经济规则、自主决策、社会消息、LLM 转述机制、日志和数据导出。 | 围绕最小闭环实现。             |
| 【确定】研究主线   | LLM 信息转述角色；框架化/情绪化分解；先机制、后后果。                    | LLM 直接决策者仅作理论对照或后续扩展。 |
| 【建议】首期经济场景 | 简化投资市场、现金/存款、收入支出、社会信息分享。                        | 足以支持跟风和交易行为指标即可。      |
| 【扩展】后续经济模块 | 复杂借贷、房地产、公司经营、复杂金融产品。                            | 核心实验稳定后再做。            |
| 【扩展】产品体验   | 完整自由模式、任务、多人联机、VR、复杂政治系统。                        | 不是毕设完成条件。             |
| 【扩展】规模美术   | 大规模 Agent、复杂城市、高端动画。                             | 先验证 5–10 个 Agent。     |

### 4. 项目边界与关键定义

* 模拟世界是封闭的，不代表真实金融市场；输出不得宣传为投资建议或现实金融预测。
* Agent 是模型化主体，其人格参数和行为规则不等同于真实人的完整心理。
* 社会信息必须是可追踪对象：原始消息、转述结果、接收范围和决策引用关系均需记录。
* LLM 输出具有不确定性，必须校验、版本化并留存原始响应。
* 涌现现象必须来自局部规则和交互，不能通过预设剧情伪造。
* Agent 与 UE 场景 NPC 分离：NPC 是表现代理，Agent 是逻辑主体。

| **概念**          | **项目内工作定义**                    | **不要混淆**      |
| --------------- | ------------------------------ | ------------- |
| Agent           | 拥有独立状态、参数、可选行为、决策记录和交互能力的模拟主体。 | 场景中的 NPC 模型。  |
| Simulation Core | 负责模拟时钟、状态更新、规则、随机数、经济事件和事件顺序。  | 渲染帧率或动画 Tick。 |
| 社会信号            | 来自其他 Agent 的观点、情绪、行为描述或消息聚合结果。 | 市场价格等公开信号。    |
| 信息转述            | 把原始社会消息整理、归纳或转换为结构化社会信号。       | 直接生成买卖行动。     |
| 框架化             | 观点结构、权重、分歧呈现或叙事组织方式的改变。        | 简单情绪正负变化。     |
| 情绪化             | 转述后情绪强度、极性或表达相对原始输入的偏移。        | 观点收敛本身。       |

## 第二部分 研究问题、理论框架与假设

### 5. 研究定位与核心问题

研究定位从早期“LLM 增强 Agent 是否更容易羊群行为”，收敛为“LLM 在 Agent 决策链中处于不同角色时，可能产生不同的行为效应”。首期聚焦信息转述者/信息接口：LLM 不替 Agent 决策，而是把 Agent 间自然语言社会信息转换为结构化信号，影响 Agent 的决策依据。

| 核心研究问题 RQ｜当 LLM 从决策者转变为 Agent 之间的社会信息转述者时，它是否会对原始社会信息产生系统性的框架化与情绪化重构？这种重构在何种条件下、通过何种机制，影响 Agent 的经济行为，并在群体层面形成可测量的羊群行为特征？ |
| ------------------------------------------------------------------------------------------------------------------------- |

### 6. LLM 在决策链中的角色框架

| **角色**   | **介入位置**                | **可能改变对象**            | **首期定位**  |
| -------- | ----------------------- | --------------------- | --------- |
| 决策者      | 直接输出买卖或行动决策。            | 行动选择本身。               | 【扩展】非核心。  |
| 信息源      | 提供外部知识或市场解释。            | Agent 可获得的信息集合。       | 【扩展】后续比较。 |
| 信息转述者/接口 | 归纳、转述其他 Agent 的言论和社会情绪。 | 社会信号的表达、框架、情绪强度和观点分布。 | 【确定】核心角色。 |
| 记忆增强者    | 整理历史事件、交互和经验。           | Agent 可调用的历史信息。       | 【扩展】后续角色。 |

研究重点是观察 LLM 如何改变 Agent“看到什么、如何理解社会信息”，而不是让 LLM 替 Agent 决策。这样可以相对独立地控制信息输入层与行动选择层。

### 7. 理论机制链与边界

| **环节** | **机制陈述**                        | **需要记录的证据**                |
| ------ | ------------------------------- | -------------------------- |
| 原始信息   | Agent 产生带方向、情绪和不确定性的自然语言消息。     | 消息原文、发送者、时间、来源事件、基准标签。     |
| 转述处理   | LLM 可能选择性压缩、重组观点、改变情绪强度或加入叙事结构。 | 模型、Prompt、输入批次、原始响应、结构化输出。 |
| 社会信号   | 接收者获得方向、置信度、情绪强度、分歧度等信号。        | 转述信号及与原始消息的映射。             |
| 决策依据   | 固定规则处理私有、公开、社会信号。               | 信号、权重、候选动作、评分和最终动作。        |
| 群体后果   | 个体行动在时间和网络中累积。                  | 跟风率、趋同度、资产变化和群体统计。         |

| 理论谨慎原则｜“LLM 天然具有大众认知特征”不是无条件事实，而是依赖任务、Prompt、模型和输入分布的理论解释。观察到转述偏向也不能仅凭结果推断其来源一定是训练语料。 |
| ------------------------------------------------------------------------------------- |

### 8. 研究假设 H1–H6

| **编号**   | **假设表述**                                         | **层级/主要观测**             |
| -------- | ------------------------------------------------ | ----------------------- |
| H1 主假设   | 相较规则转述，LLM 转述更倾向放大情绪与叙事收敛，并可能进一步加剧群体羊群行为。        | 机制层与群体层；转述偏差、跟风率。       |
| H2 剂量假设  | LLM 社会信号在决策中的影响权重越高，转述偏向对群体行为影响越强。               | 群体层；0/20/50% 等权重梯度。     |
| H3 调节假设  | 市场不确定性越高，转述偏向对群体行为影响越强。                          | 群体层；高/低不确定性与交互效应。       |
| H4 机制假设  | 转述偏向主要通过改变社会信号相对作用、提高私有信号被忽略概率传导为跟风，而非直接改变风险偏好。  | 群体层；信号权重、信息忽略率、风险参数稳定性。 |
| H5 分解假设  | 转述偏向可分解为框架化与情绪化两个可分别测量的维度；二者对群体行为的作用可能不同。        | 机制/群体层；分歧度压缩、叙事化、情绪偏差。  |
| H6 稳健性假设 | 多个中性 Prompt 变体下若偏向相对规则基准稳定存在，则支持其不依赖单一叙事引导措辞的解释。 | 机制层；至少 2–3 个中性变体。       |

H1 的机制层与群体层必须分别报告。若机制层有偏向而群体层未观察到稳定后果，应表述为“机制存在但当前模型条件下未观察到群体传导”，不能合并成简单成功/失败。

### 9. 假设的可证伪条件

| **假设** | **不支持的可能结果**                      | **解释要求**               |
| ------ | --------------------------------- | ---------------------- |
| H1     | 中性 LLM 与规则转述无显著差异；或有偏向但群体指标无稳定变化。 | 区分机制不存在与机制未传导。         |
| H2     | 权重梯度无趋势或方向相反。                     | 检查非线性、统计功效和权重定义。       |
| H3     | 高不确定性下效应不增强。                      | 检查不确定性定义及外部冲击混淆。       |
| H4     | 风险参数变化或信息忽略率不承担路径。                | 先检查实现越界，再修正理论。         |
| H5     | 框架化与情绪化指标无法区分。                    | 重新定义指标，不强行支持双维度。       |
| H6     | 不同中性 Prompt 结果方向或幅度不稳定。           | 报告 Prompt 敏感性，不声称偏向稳健。 |

## 第三部分 产品功能与模拟世界设计

### 11. 产品定位与三种模式

| **模式** | **用户身份** | **主要能力**                                 | **优先级**            |
| ------ | -------- | ---------------------------------------- | ------------------ |
| 实验模式   | 研究者      | 配置实验条件、转述方式、权重、不确定性、重复次数；运行实验、查看指标、导出数据。 | 【确定】研究主界面。         |
| 导演模式   | 观察者/导演   | 选择 Agent 查看参数、状态、关系、资产和行为轨迹；暂停、加速、回放。    | 【建议】核心闭环后实现。       |
| 自由模式   | 参与者      | 控制角色移动、工作、交易、投资、娱乐和社交。                   | 【扩展】沉浸体验，不是首期必要条件。 |

### 12. 最小模拟世界

首期建议一个小型社区或市场场景。House、Plaza、Shop、Office 等仅作为占位空间。世界空间首先服务行为可观察性：Agent 在何处工作、消费、交流或交易，应能在逻辑数据中表示，并可映射为展示层位置。

| **世界要素** | **逻辑职责**            | **首期要求**            |
| -------- | ------------------- | ------------------- |
| 地点       | 工作、居住、消费、社交等行为上下文。  | 可先用抽象 Location ID。  |
| 模拟时间     | 统一推进日、周、月或离散周期。     | 独立于渲染帧率，支持暂停和倍速。    |
| Agent    | 持有状态、参数、关系、记忆和行为。   | 建议先 5–10 个，逻辑与表现分离。 |
| 经济环境     | 工资、消费、存款、市场价格和外部冲击。 | 简化市场足以支持研究指标。       |
| 社会网络     | 消息、熟悉度、信任和传播。       | 首期关系字段可控制在熟悉度、信任。   |
| 观察工具     | 状态面板、事件流、统计图和导出。    | 优先于精致 UI 和动画。       |

### 13. Agent 数据分层

| **层次** | **字段示例**                                                                                            | **设计约束**              |
| ------ | --------------------------------------------------------------------------------------------------- | --------------------- |
| 身份     | agent\_id、name、age、occupation、home/work\_location。                                                  | 稳定 ID，不用显示名称做主键。      |
| 经济状态   | cash、deposit、debt、income、expense、asset\_value、net\_worth。                                           | 由经济事件更新，记录前后值。        |
| 行为参数   | risk\_preference、spending\_tendency、saving\_tendency、information\_sensitivity、investment\_patience。 | 建议 0–1；实验期间原则上固定。     |
| 社会关系   | familiarity、trust、influence（可选）。                                                                    | 有向/无向关系待技术设计明确。       |
| 认知信息   | private\_signal、public\_signal、social\_signal、belief、known\_events。                                 | 区分客观世界、已知信息和主观信念。     |
| 行为状态   | working、shopping、socializing、traveling、sleeping 等。                                                  | 状态机/调度方式待定。           |
| 历史记录   | decision\_history、interaction\_history、important\_events。                                           | 先用结构化有限记忆，不首期引入复杂向量库。 |

### 14. Agent 决策流程

| **步骤** | **职责**                          | **输出**          |
| ------ | ------------------------------- | --------------- |
| 状态读取   | 读取经济状态、行为状态、信号和相关关系。            | 决策上下文。          |
| 候选行为生成 | 从当前可行动作集合生成候选项。                 | 候选动作列表。         |
| 约束过滤   | 排除资金不足、市场关闭等不可行动作。              | 可执行候选项。         |
| 规则评分   | 按固定、可配置规则计算候选动作得分。              | 候选动作评分。         |
| 行动选择   | 确定性规则或受控随机选择。                   | chosen\_action。 |
| 验证执行   | Simulation Core 验证并应用经济/社会状态变更。 | 事件与新状态。         |
| 记录     | 保存信号、候选项、评分、动作、结果和随机数上下文。       | DecisionLog。    |

| 关键隔离｜LLM 可以影响 social\_signal 的结构化表达；不得直接改写 risk\_preference、private\_signal、cash、debt、资产所有权或最终 World State。 |
| ----------------------------------------------------------------------------------------------------------- |

### 15. 经济系统范围

| **模块**  | **基础功能**             | **研究用途**      | **首期状态**    |
| ------- | -------------------- | ------------- | ----------- |
| 现金与存款   | 现金、存款、利率、工资、基础支出。    | 经济状态基础。       | 【确定】最小闭环。   |
| 投资市场    | 简化资产、价格序列、买卖、市场波动。   | 跟风、交易频率、情绪敏感。 | 【建议】首期简化实现。 |
| 借贷      | 借款、还款、利息、违约、信用/信任影响。 | 经济关系和社会约束。    | 【建议】可简化或后置。 |
| 信息分享    | Agent 交流观点、传播市场信息。   | LLM 转述核心输入。   | 【确定】首期必须。   |
| 娱乐/风险活动 | 概率事件和风险暴露。           | 辅助观察风险偏好。     | 【扩展】谨慎控制范围。 |
| 房地产/公司  | 产权、租金、企业收入、雇佣。       | 复杂经济结构。       | 【扩展】非 MVP。  |

### 16. 最小闭环与涌现场景

最小闭环：初始化 Agent 与经济环境 → 模拟时间推进 → Agent 工作获得收入 → 消费/储蓄 → 获取市场与社会信息 → 按固定规则决策 → 执行经济行为 → 产生消息和关系变化 → 记录事件与状态 → 观察和导出结果。

首个测试场景可采用：Agent A 工作获得工资 → 发生交易/风险行为 → 现金减少 → 向 Agent B 借款 → B 根据资金、关系和风险约束决定接受或拒绝 → 双方经济状态与关系更新。该场景是工程测试用例，不是研究结论。

### 18. 逻辑模块划分（技术无关）

| **模块**           | **单一职责**                   | **输入/输出契约**                                  |
| ---------------- | -------------------------- | -------------------------------------------- |
| SimulationClock  | 模拟时间、步长、暂停/倍速。             | 配置与控制命令 → SimTime/Tick 事件。                   |
| SimulationCore   | 编排每个周期的更新顺序。               | Clock、World、规则 → 稳定事件序列和快照。                  |
| AgentSystem      | 管理 Agent 状态、候选动作和决策。       | 状态/信号/关系 → DecisionLog/ActionIntent。         |
| EconomySystem    | 工资、消费、存款、交易、借贷和资产变更。       | 已验证 ActionIntent → EconomicEvent/StateDelta。 |
| SocialSystem     | 消息、关系、传播范围和社会信号。           | 原始消息/关系/转述结果 → SocialMessage/SocialSignal。   |
| LLMAdapter       | 供应商、Prompt、请求、解析、缓存、超时和回退。 | RelayRequest → ValidatedRelayResult 或失败状态。   |
| ExperimentRunner | 初始化实验、组别、种子和重复运行。          | ExperimentConfig → RunManifest/运行状态。         |
| DataRecorder     | 原始输入、响应、决策、事件、快照和指标记录。     | 系统事件 → 可查询、可导出数据。                            |
| Presentation     | 展示场景、Agent、时间、事件、状态和图表。    | 快照/事件流 → 可视化，不直接修改模拟事实。                      |
| Analysis         | 指标计算、统计比较和图表。              | 标准数据集 → MetricResult/报告。                     |

### 19. 模块依赖与不可破坏原则

* 表现层可发送暂停、加速、选择 Agent、开始实验等命令，但不得直接改写 Agent 资产或市场价格。
* 所有经济状态变更由 EconomySystem 或对应规则执行，并产生事件记录。
* AgentSystem 不直接访问某家模型 SDK，只消费 SocialSignal 或 RelayResult。
* ExperimentRunner 负责运行编排，不实现经济规则。
* DataRecorder 不能只存最终图表，必须保留可追溯过程数据。
* 模拟时间与 UE Frame Tick 解耦；UE 原生路线也需保持逻辑时间与渲染帧率分离。

### 20. 核心数据流与故障处理

#### 20.1 模拟更新流

SimulationClock → SimulationTick → World Update → Agent Update → Candidate Actions → Decision → Economy/Social Events → Data Logging → Snapshot/Presentation。阶段顺序必须固定并记录周期编号。

#### 20.2 LLM 转述流

原始 Agent 消息 → 批次构造 → Prompt/模型配置绑定 → LLM 请求 → 原始响应保存 → JSON 解析 → 字段/范围校验 → 建议内容检测 → 结构化 SocialSignal → 固定规则评分 → Simulation Validation → World State Mutation。

#### 20.3 故障回退

超时、供应商错误、JSON 无效、字段缺失或越界时，返回明确失败状态；可按实验配置重试、用缓存、回退规则转述或标记批次无效。不能静默把回退结果当成有效 LLM 输出。

### 21. 两条路线比较与选择 Gate

| **维度** | **Python + UE**   | **UE 原生 C++/Blueprint** |
| ------ | ----------------- | ----------------------- |
| 实验吞吐   | 适合批量模拟和数据处理，仍需实测。 | 进程内集成直接，但批量实验工具链需规划。    |
| UE 深度  | UE 侧重展示，模拟逻辑较解耦。  | 更深入引擎对象、生命周期和调试。        |
| 语言学习   | Python 作为实验与分析主力。 | C++/Blueprint 成为主要工程路线。 |
| 数据分析   | 与统计工具衔接自然。        | 需规范导出外部分析。              |
| 主要风险   | 通信同步、状态一致性。       | 逻辑与引擎生命周期耦合。            |
| 优先目标   | 研究机制与实验复现。        | UE 工程能力与一体化。            |

| **Gate** | **验证任务**                            | **决策依据**      |
| -------- | ----------------------------------- | ------------- |
| G1       | 实现 5 Agent、模拟时钟、工资/消费、固定 seed、事件日志。 | 独立运行、测试和重复。   |
| G2       | 批量运行并记录耗时、内存、失败率。                   | 是否支持研究重复次数。   |
| G3       | 批量转述、JSON 校验、缓存和失败回退。               | 接口复杂度、成本和稳定性。 |
| G4       | 将状态快照/事件流映射到 UE 最小场景。               | 同步、延迟、可视化成本。  |
| G5       | 模块开发、测试、调试、数据导出。                    | 个人可维护性。       |

| 路线冻结条件｜至少完成 G1–G4 小型验证并形成决策记录后，才冻结模拟核心路线。视觉路线可单独决定。 |
| --------------------------------------------------- |

### 22. 视觉路线（独立待定）

| **路线**  | **优势**             | **成本/风险**             | **适用判断**      |
| ------- | ------------------ | --------------------- | ------------- |
| 2D 俯视   | 资产和镜头控制相对简单，信息密度高。 | 空间沉浸感较弱。              | 研究可读性、快速交付优先。 |

## 第五部分 实验设计、数据采集与分析

### 23. 三层实验架构

| **层级**     | **内容**                           | **目的**            | **优先级**     |
| ---------- | -------------------------------- | ----------------- | ----------- |
| 第一层：模拟载体   | Agent、经济系统、信息分享、数据记录。            | 提供受控环境和可重复运行能力。   | 基础前提。       |
| 第二层：转述机制实验 | 同一批输入比较规则、多个中性 Prompt、叙事引导和理性引导。 | 独立测量转述偏向，是首期核心贡献。 | 【确定】优先。     |
| 第三层：群体后果实验 | 不同转述方式接入 ABM，比较跟风、趋同、信息忽略等。      | 检验转述偏向是否传导为群体后果。  | 【建议】第二层稳定后。 |

### 24. 第二层：转述机制实验

#### 24.1 输入集构造

CC 第三版提出 50 组原始发言集、每组约 100 条，建议包含偏看涨、偏看跌和中性输入。V1.1 保留为设计起点而非硬性规模承诺。输入集必须在实验前构造、保存并预先标注基准统计量。

| **字段**                                | **说明**                |
| ------------------------------------- | --------------------- |
| dataset\_id / batch\_id               | 输入集合和批次唯一标识。          |
| message\_id / speaker\_id             | 消息和发送者标识；合成数据需记录生成规则。 |
| raw\_text                             | 原始消息文本。               |
| ground\_truth\_direction              | 看涨/看跌/中性标签及标注规则。      |
| ground\_truth\_sentiment              | 情绪极性/强度基准及量表。         |
| source\_group                         | 偏看涨、偏看跌、中性等输入类别。      |
| dataset\_version / annotation\_method | 版本与标注方式，说明规则/人工/双重标注。 |

#### 24.2 转述条件

| **条件**   | **描述**                  | **用途**            |
| -------- | ----------------------- | ----------------- |
| R 规则基准   | 预先定义的关键词/词典或统计规则。       | 非 LLM 基准；需说明规则误差。 |
| L0-a/b/c | 措辞不同但语义中性的 Prompt，不加建议。 | 检验是否依赖单一措辞，支撑 H6。 |
| L1 叙事引导  | 要求总结市场故事和主流情绪。          | 探索叙事引导的影响。        |
| L2 理性引导  | 要求指出分歧、风险和不确定性，不给买卖建议。  | 探索理性约束的抑制作用。      |

L1/L2 与 L0 的比较在原始设计中属于探索性分析，不应未经预注册就升级为主要确认性假设。所有 Prompt 必须保存完整文本、版本号和修改记录。

#### 24.3 结构化输出建议

| **字段**               | **类型/范围**                     | **定义**             |
| -------------------- | ----------------------------- | ------------------ |
| direction\_counts    | bullish/bearish/neutral 整数或比例 | 转述后的方向类别计数。        |
| sentiment\_intensity | 0–1                           | 总体情绪强度；需定义标注或评分方法。 |
| disagreement         | 0–1                           | 观点分歧程度；固定计算规则。     |
| key\_terms           | 字符串数组                         | 代表性词语及抽取规则。        |
| narrative\_features  | 可选对象                          | 故事性词汇、因果句式等特征。     |
| confidence           | 可选 0–1                        | 模型自评置信度，不等于真实准确率。  |
| schema\_version      | 字符串                           | 输出模式版本。            |

#### 24.4 五项核心测量

| **指标** | **建议定义**                  | **解释注意**         |
| ------ | ------------------------- | ---------------- |
| 情绪强度偏差 | 转述后情绪强度 − 原始基准情绪强度。       | 正值增强、负值减弱；量表需一致。 |
| 分歧度压缩率 | (原始分歧度 − 转述后分歧度) / 原始分歧度。 | 原始分歧为 0 时需预定义处理。 |
| 叙事化程度  | 故事性词汇比例、因果句式比例或人工编码得分。    | 需制定标注规则并报告一致性。   |
| 选择性偏差  | 转述后方向比例与原始方向比例之差。         | 分别计算看涨/看跌方向。     |
| 判断比例   | 输出中建议、判断、规范性语句占比。         | 操纵检验和越界检查。       |

#### 24.5 核心比较

* L0-a/b/c 与 R：比较中性变体是否存在方向一致、幅度可解释的偏差；变体间稳定性是 H6 关键。
* L1 与 L0：探索叙事引导是否改变情绪强度、叙事化程度或分歧度。
* L2 与 L0：探索理性引导能否降低偏差，注意理性引导本身也会引入框架。
* 框架化与情绪化交叉分析：判断两者是否可区分，避免单一“叙事化”标签概括所有变化。

### 25. 第三层：群体后果实验

| **组别**    | **信息处理**           | **决策规则**                 | **控制条件**             |
| --------- | ------------------ | ------------------------ | -------------------- |
| A 规则组     | 规则转述/统计。           | 固定规则 + 私有 + 公开 + 规则社会信号。 | Agent、资产、人格、市场、时长匹配。 |
| B LLM 转述组 | 指定 L0 条件生成结构化社会信号。 | 与 A 组相同固定规则，只替换社会信号。     | 其余条件尽量一致。            |

首期优先比较 R 与预先选定的中性 L0。L1/L2 可作扩展条件。若组间决策规则、人格分布或私有信号不同，就无法把差异归因于转述层。

| **类别** | **变量**                           | **建议水平/控制**                      |
| ------ | -------------------------------- | -------------------------------- |
| 自变量    | 转述方式                             | R / L0-a / L0-b / L0-c；L1/L2 探索。 |
| 自变量    | 社会信号权重                           | 0%、20%、50% 为初始建议，最终由预试验决定。       |
| 自变量    | LLM 增强比例                         | 0%、50%、100% 可选；与权重区分。            |
| 调节变量   | 市场不确定性                           | 高/低，用预定义波动率或外部冲击构造。              |
| 控制变量   | Agent 数量、人格分布、初始资产、价格序列、周期、消息节奏。 | 同一条件匹配；必要时配对种子。                  |
| 记录变量   | 模型版本、温度、输出长度、Prompt、调用时间、缓存状态。   | 写入 RunManifest。                  |

### 26. 群体行为指标

| **指标**   | **定义建议**                       | **优先级**      |
| -------- | ------------------------------ | ------------ |
| 跟风率      | 决策方向与预定义群体多数方向一致的比例；明确窗口和平票处理。 | 主指标。         |
| 决策趋同度    | 同一期 Agent 决策分布离散程度/方差；定义离散编码。  | 辅助。          |
| 信息忽略率    | 私有信号与行动冲突且行动更贴近社会信号的比例。        | 辅助/机制。       |
| 交易频率/换手率 | 单位模拟时间内交易次数或交易量/资产规模。          | 扩展。          |
| 处置效应     | 盈利资产与亏损资产的卖出概率差。               | 扩展，需持仓与盈亏记录。 |
| 情绪敏感度    | 决策与社会情绪信号变化的关联。                | 扩展。          |
| 注意力集中度   | 交易分布在资产间的集中程度，如 HHI。           | 扩展。          |
| 过度反应     | 消息/价格冲击前后交易量或行动变化。             | 扩展。          |

首期建议跟风率为主指标，趋同度和信息忽略率为辅助；交易频率可作为低成本扩展。处置效应、注意力集中和过度反应需要更完整的持仓/资产模型。

### 27. 实验单位、重复次数与统计报告

* 第二层实验单位：固定输入批次在某一转述条件下的一次输出；同一批次跨条件配对比较。
* 第三层实验单位：一次完整模拟运行（run），不是单个 Agent 或单个 Tick。Agent/Tick 观测嵌套于 run，不能简单视为独立样本。
* 原始材料建议每组 30–50 轮；V1.1 将其视为初始目标，最终次数应结合预试验方差、预期效应、预算和统计功效决定。
* 固定或记录随机种子；相同 seed 不保证外部 API 输出完全可复现。
* 正式实验前定义主指标、主要比较和排除规则，避免结果出来后不断更换指标。
* 报告样本量、均值/中位数、离散程度、效应量、置信区间、检验方法和多重比较处理。
* t 检验、Mann–Whitney U、回归和交互项模型须结合数据结构和统计假设选择。
* 中介分析需要时间顺序、测量和混淆控制；证据不足时报告机制关联，不声称严格因果中介。

### 28. 数据采集流程

| **阶段** | **产物**                               | **验收要求**          |
| ------ | ------------------------------------ | ----------------- |
| 预实验    | 输入集、Prompt、schema、少量运行记录。            | 发现格式、指标边界和成本问题。   |
| 正式运行   | RunManifest、原始输入/响应、结构化结果、决策/事件日志。   | 每个结果可追溯到条件、模型和版本。 |
| 清洗校验   | 质量报告、无效批次、缺失/异常统计。                   | 排除规则预先定义并留痕。      |
| 指标计算   | MetricResult 与 calculation\_version。 | 同一数据同一版本得到一致结果。   |
| 统计图表   | 表格、箱线图、时间序列、条件比较图。                   | 图表可从原始数据重建。       |
| 结论讨论   | 假设支持/不支持/不确定及边界。                     | 区分统计差异、效应大小和因果解释。 |

## 第六部分 开发路线、里程碑与任务管理

### 29. 开发总策略

| 开发哲学｜先做出一个极小但完整的社会，再不断扩大；先让世界运行，再让世界变复杂，最后让世界变得有意义。 |
| --------------------------------------------------- |

开发顺序：Vertical Slice → Core Simulation → Social System → LLM → Experiment → Presentation/Director Mode → Optimization。研究机制实验可在没有完整 UE 场景时独立推进；UE 可视化不是研究数据有效性的前置条件。

### 34. 通用 DoD 模板

* 功能可从指定入口运行，不依赖手工修改隐藏状态。
* 关键输入、输出和状态变更有结构化日志。
* 正常路径和至少一个异常路径有测试。
* 配置参数有默认值、范围和说明，不硬编码实验参数。
* 变更不破坏核心测试；必要时更新 schema 版本。
* 复杂决策规则附公式或伪代码。
* 任务完成后更新 README 或设计记录，说明验证方法。

时间安排不按固定日历承诺冻结。建议按依赖顺序推进：课程/毕业要求与最小模拟核心 → 转述机制实验 → 群体实验 → UE 表现和展示。每周目标以可验收产物而不是学习时长作为单位。

### 35. 风险登记表

| **风险**    | **原因/表现**                 | **控制措施**                  | **降级方案**         |

### 44. 面试讲解要点

* 为什么不让 LLM 直接交易？为分离信息处理与行动规则，便于控制变量和追溯。
* 如何避免 Prompt 人为诱导？多个中性变体、规则基准、Prompt 保存和操纵检验。
* 叙事化如何定义？拆成框架化、情绪化等可独立测量维度。
* 如何证明不是脚本动画？展示状态驱动决策、事件日志、异质参数和无人干预运行。
* LLM API 失败怎么办？超时、重试、校验、缓存和规则回退，回退样本单独标记。
* 假设不成立怎么办？如实报告，讨论模型、Prompt、基准规则、输入分布和模拟环境边界。

| pause/resume                                     | 运行控制。                     | 控制状态。                |

| submit\_social\_messages(messages)               | 原文、发送者、时间、来源事件。           | message\_id 列表、校验状态。 |
| relay\_batch(batch\_id, method, prompt\_version) | 输入批次、转述方式、Prompt 版本。      | 结构化结果、模型元数据、校验状态。    |
| export\_run(run\_id, format)                     | 运行 ID 和格式。                | 导出状态、schema 版本。      |
| replay\_run(run\_id)                             | 运行 ID。                    | 按事件重建展示状态，不改原始实验数据。  |

以上是逻辑契约，不是已经选定的 REST API、Python 函数或 UE C++ 方法签名。具体协议、字段类型、错误码和序列化格式在技术路线确定后写入技术设计文档。

## 附录 C LLM 转述校验清单

* 输入批次是否有唯一 ID，是否保存原始消息和顺序？
* Prompt 是否有版本号，完整文本是否留存？
* 模型名称、版本、参数、调用时间和供应商是否记录？
* 响应是否先保存原文，再解析？
* JSON 是否通过 schema 校验，数值是否在合法范围？
* 输出是否包含建议、预测或行动指令等越界内容？
* 失败、重试、缓存命中和规则回退是否有不同状态标记？
* 任一 SocialSignal 是否可追溯到输入消息集合？

## 附录 F 项目验收快速检查表

* □ 模拟核心可脱离玩家输入持续运行。
* □ 模拟时间独立于渲染帧率。
* □ 至少 5 个 Agent 拥有不同初始状态和参数。
* □ 经济事件有前后状态记录。
* □ 社会消息可追溯发送者和来源事件。
* □ LLM 输出不直接修改世界状态。
* □ 规则转述与 LLM 转述使用相同输入批次比较。
* □ 至少 2–3 个中性 Prompt 变体可运行。
* □ 指标定义和计算版本固定。
* □ 实验配置、seed、模型和 Prompt 版本可追溯。
* □ 失败回退样本与有效 LLM 样本区分。
* □ 图表可从原始数据重新生成。
* □ README 可让他人在干净环境启动。
* □ Demo、论文、答辩和简历表述与真实实现一致。
